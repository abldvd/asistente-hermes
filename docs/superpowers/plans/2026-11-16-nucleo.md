# Asistente Hermes — Plan 1: Núcleo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar Hermes Agent funcionando en Windows nativo con modelo local elegido por pruebas, Telegram, autoarranque, y las piezas Python compartidas (compuerta de juego/uso, tope de Claude) que usarán los módulos de los planes 2 y 3.

**Architecture:** El repo `E:\asistente-hermes` es la fuente de verdad. Un paquete Python pequeño (`asistente/`) implementa las reglas deterministas (¿hay juego?, ¿hay cuota de Claude?, ¿toca ejecutar hoy?, llamar a `claude -p` con tope). Hermes las invoca como scripts desde skills y cron. `aplicar.ps1` copia la configuración del repo a `~/.hermes`.

**Tech Stack:** Hermes Agent ~0.23 (Windows nativo), Ollama, Python 3.10 (`C:\Users\usuario\AppData\Local\Programs\Python\Python310\python.exe`, la misma base que el Job Hunter) + pytest, PowerShell 5.1, Claude Code CLI (`claude`), OpenRouter (modelos `:free`).

**Spec:** `E:\asistente-hermes\docs\2026-11-16-asistente-hermes-design.md`

**Alcance:** este plan cubre las fases 0, 1 y 3 del diseño, más la prueba de DirectSDK. Los planes 2 (correo, calendario, sugerencias de eventos) y 3 (Job Hunter y noticias) se escriben al terminar este, porque dependen del modelo elegido en la fase 0.

## Global Constraints

- Nunca `--dangerously-skip-permissions` ni `--permission-mode bypassPermissions` en ninguna llamada a `claude`.
- Nunca proveedor `anthropic` con API key. Claude solo vía suscripción (`claude -p` o el plugin DirectSDK).
- Correo y calendario nunca se envían a OpenRouter (afecta a la configuración de la tarea 7 en adelante).
- Uso de 5 h: umbral 80 % (`~/.claude/uso-5h.json`, campos `pct` y `t` en epoch s). Dato fresco = `t` con menos de 5 h de antigüedad.
- Tope de llamadas a Claude: 10 al día (configurable).
- Retrasos por juego o cuota: bloques de 30 min, máximo 4 h desde el primer intento del día; después, se salta y se avisa.
- Ollama: contexto ≥ 64000 tokens para Hermes; `OLLAMA_KEEP_ALIVE=5m`.
- Zona horaria `Atlantic/Canary`.
- Secretos en `E:\asistente-hermes\secretos\.env` (en `.gitignore`); nunca en el repo ni en `config/`.
- Mensajes de commit en inglés.
- Hermes: verificar cada comando o clave contra `hermes --help`/docs antes de usarlo; si difiere de este plan, gana la documentación y se anota en `docs/notas-hermes.md`.

## Review Focus

1. **`uso-5h.json` ausente, vacío o corrupto** → tratarlo como dato no fresco (solo llamadas explícitas). Nunca romper. Test en la tarea 2.
2. **Cambio de día con un retraso a medias** (primer intento a las 23:00 y comprobación a las 00:30) → el estado del día anterior no bloquea el día nuevo. Test en la tarea 4.
3. **`nvidia-smi` no disponible o con salida rara** → `gpu_util()` devuelve `None` y se decide solo por procesos. Test en la tarea 3.
4. **Dos ejecuciones simultáneas de la compuerta o del contador** (cron y chat a la vez) → la escritura de estado es atómica (tmp + `os.replace`) y el contador no se queda por debajo del real de forma grave. Test de escritura atómica en la tarea 1.
5. **`claude` falla o tarda** (sin login, timeout) → el wrapper devuelve un error legible, con código ≠ 0, y **sí** cuenta la llamada solo si el proceso llegó a arrancar. Test en la tarea 5.

### Task 4: Compuerta de tareas programadas

Permite a cada cron de Hermes correr cada 30 min en una ventana (p. ej. de 08:00 a 23:30) y que la compuerta decida. Así se cubren a la vez los retrasos por juego o cuota y las ejecuciones perdidas con el PC apagado, sin disparador de Windows.

**Files:**
- Create: `asistente\compuerta.py`
- Test: `tests\test_compuerta.py`

**Interfaces:**
- Consumes: tareas 1-3.
- Produces:
  - `decidir(tarea: str, ahora: datetime, juego: bool, cuota_ok: bool, estado: dict, retraso_max_h: float) -> tuple[str, dict]`. Devuelve una decisión de `{"EJECUTAR", "ESPERAR", "SALTAR", "HECHO", "YA_SALTADO"}` y el estado nuevo, con la forma `{"fecha": str, "primer_intento": iso | None, "hecho": bool, "saltado": bool}`; si `fecha` ≠ hoy, se reinicia.
  - CLI `python -m asistente.compuerta --tarea NOMBRE [--requiere-claude]`: imprime una línea `DECISION: <X> — <motivo>` y sale con código 0 = EJECUTAR, 10 = ESPERAR, 11 = SALTAR (avisar), 12 = HECHO o YA_SALTADO (silencio).
  - `python -m asistente.compuerta --tarea NOMBRE --hecho`: marca la tarea como hecha hoy.
  - Estado en `compuerta_<tarea>.json`.

  Orden en `decidir`:
  1. `hecho` → HECHO.
  2. `saltado` → YA_SALTADO.
  3. Si hay juego o falta cuota: registra `primer_intento` si no existe; si `ahora − primer_intento > retraso_max_h` → SALTAR (marca `saltado`); si no, ESPERAR.
  4. En otro caso → EJECUTAR.

- [ ] **Step 1: Tests que fallan**
  - Estado vacío, sin juego, con cuota → `EJECUTAR`
  - `juego=True` a las 08:00 → `ESPERAR` y `primer_intento` = 08:00
  - El mismo estado a las 12:01 con juego → `SALTAR` y `saltado=True`; a las 12:31 → `YA_SALTADO`
  - Estado con `hecho=True` → `HECHO`
  - Estado de ayer con `saltado=True` → hoy, sin juego → `EJECUTAR` (Review Focus 2)
  - `juego=True` a las 23:00 de ayer, y a las 00:30 de hoy sin juego → `EJECUTAR`
- [ ] **Step 2:** Ejecutar → FAIL.
- [ ] **Step 3:** Implementar `decidir` y la CLI. `cuota_ok` solo se evalúa con `--requiere-claude`, mediante `puede_usar_claude(..., explicito=False)`.
- [ ] **Step 4:** Ejecutar → PASS. Prueba manual: `.venv\Scripts\python -m asistente.compuerta --tarea prueba; echo $LASTEXITCODE` → `DECISION: EJECUTAR` y `0`.
